# iPhoneのヘルスケアをLifelogへ自動送信する設定手順

歩数・消費カロリー・体組成・睡眠を、**1つのショートカットでまとめて** Lifelog に送ります。
既存の「eufy体組成計の手順」(`docs/eufy-healthkit-setup.md`) を置き換えるものです。
体組成だけの古いショートカットを使い続けても動きますが、こちらに乗り換えると設定が1つで済みます。

## 事前に用意するもの

次の3つを先に手元に揃えてください。Scriptable ウィジェット `scripts/lifelog-widget.js` を設定済みなら、
`USER_ID` / `WIDGET_TOKEN` に入れたものと同じ値を使います。

### ① uid（FirebaseのユーザーID）

Googleログインしたときに Firebase が発行する、自分専用の28文字前後の英数字です。
アプリの画面には出していないので、Firebase コンソールから取ります。

1. https://console.firebase.google.com/project/lifelog-14b58/authentication/users を開く
   （プロジェクト `lifelog-14b58` →「構築」→「Authentication」→「Users」タブ）
2. ログインに使っている Google アカウントの行を見る
3. 「**ユーザー UID**」列の値（`kJ8xY2mNpQ...` のような文字列）をコピーする

これが `uid` です。ウィジェットの `USER_ID` にも同じ値を入れます。

### ② WIDGET_TOKEN

**これはどこかから発行されるものではなく、自分で決める合言葉です。**
ショートカットから API を叩くときの本人確認にだけ使われ、サーバー側は値が一致するかを見ているだけです。

1. ランダムな文字列を作る（`openssl rand -hex 24` か、パスワード生成ツールで32文字程度）
2. Vercel → 該当プロジェクト →「Settings」→「Environment Variables」を開く
3. Name に `WIDGET_TOKEN`、Value に作った文字列を入れて保存
   （Environments は Production。Preview でも試すなら両方チェック）
4. **保存後に再デプロイする。** 環境変数はデプロイ時に結びつくので、既存のデプロイには反映されません
5. 同じ文字列を、ショートカットの `x-widget-token` ヘッダーとウィジェットの `WIDGET_TOKEN` に入れる

> **`WIDGET_TOKEN` が未設定だと、すべてのリクエストが 401 で弾かれます。**
> ショートカットを正しく作ってもデータが1件も入らない場合、まずここを疑ってください。

### ③ デプロイURL

`https://<プロジェクト名>.vercel.app` の形です。Vercel のプロジェクト画面に表示されている本番URLを使います。
この手順の中の `https://<デプロイURL>/api/health/sync` は、
例えば `https://lifelog-orpin.vercel.app/api/health/sync` のようになります（末尾のスラッシュは付けません）。

> **注意**: `/api/health/sync` は本番にデプロイされて初めて使えます。
> 機能を追加したブランチをマージする前に試したい場合は、
> Vercel がブランチごとに発行するプレビューURLを使ってください。

## 1. ヘルスケアに何が入っているか確認する

「ヘルスケア」→「概要」→ 一番下の「すべてのヘルスケアデータを表示」で、今どの項目にデータが入っているか見られます。
**入っていない項目はショートカットに入れても空で送られるだけ**なので、入っているものだけ設定すれば十分です。

このリポジトリの利用者の環境（2026-07-31 時点）では、次が入っていました。

| 項目 | 状態 | Lifelogでの扱い |
|---|---|---|
| 歩数 | ✅ | アクティビティカードに表示 |
| ウォーキング＋ランニングの距離 | ✅ | 同上 |
| アクティブエネルギー | ✅ | 同上 |
| 安静時消費エネルギー | ✅ | 「ほかの記録」に表示 |
| 上った階数 | ✅ | 「ほかの記録」に表示 |
| 心拍数 | ✅ | 「ほかの記録」に表示 |
| 歩行速度・歩幅・歩行非対称性・両脚支持時間 | ✅ | 「ほかの記録」に表示 |
| 体重・体脂肪率・BMI・除脂肪体重・身長 | ✅（eufy体組成計から） | 体組成として表示 |
| **睡眠** | ❌ データなし | Apple Watch か睡眠アプリを使い始めると入ります |
| **エクササイズ時間・スタンド時間** | ❌（Apple Watch が必要） | Watch を使い始めると入ります |

**体組成について**: HealthKit には「筋肉量」「体水分率」「内臓脂肪レベル」に相当する保存先が**ありません**。
EufyLife アプリ側にそれらの表示があっても、Apple ヘルスケア経由では取り出せません。
ヘルスケアから取れる体組成は、上の**5項目で全部**です。Lifelog はその5つをすべて受け取ります。

## 2. ショートカットを作る

「ショートカット」アプリ →「+」で新規作成します。名前は「Lifelog同期」など。

### ⚠️ 先に読んでください — ここで9割の人がつまずきます

**「ヘルスケアサンプルを検索」を2つ続けて置くと、2つ目が勝手に「ヘルスケアサンプルに<u>フィルタを適用</u>」に変わります。**

「フィルタを適用」は**前のアクションの結果を絞り込む**アクションです。
つまり「歩数のサンプルの中から、種類が体脂肪率のものを探す」という意味になり、**結果は必ず空**になります。
見た目がよく似ているので気づきにくく、「設定したのに何も入らない」の最大の原因です。

正しくは、**項目ごとに独立した「検索」**にする必要があります。アクションのタイトルが
「ヘルスケアサンプルを**検索**」になっているか、1つずつ必ず確認してください。
「フィルタを適用」になっていたら、そのアクションを削除して、
**アクション検索欄から「ヘルスケアサンプルを検索」を選び直して**追加します。

### 2-0. まず1項目だけで通してみる

12項目を一度に組んでから動かすと、どこが悪いのか分からなくなります。
**最初は歩数だけ**でショートカットを作り、成功を確認してから項目を増やしてください。

### 2-1. 1項目ぶんの作り方（歩数の例）

1項目につき **3つのアクション**をこの順に置きます。

**① ヘルスケアサンプルを検索**

| 設定項目 | 値 |
|---|---|
| 種類 | 歩数 |
| 開始日 | が今日である |
| 単位 | 歩 |
| 並び順 | なし |
| 制限 | **オフ**（1日ぶん全部のサンプルが必要） |

**② 統計を計算**

- 入力: ①の結果（ヘルスケアサンプル）
- 操作: **合計**

> **なぜ必要か**: 歩数は1日に何十件ものサンプルに分かれて記録されます。
> ①で「制限オン・取得1項目」にすると、**最新の1件（数十歩）しか取れません**。
> 1日の合計にするには、必ず「統計を計算 → 合計」を通してください。

**③ 変数を設定**

- 名前: `歩数`（あとで JSON に差し込むときの目印）

これで1項目ぶんが完成です。ほかの項目も同じ3点セットで追加していきます。

### 2-1b. 項目ごとの設定一覧

| 項目 | 種類 | 単位 | ②統計を計算 | 変数名 |
|---|---|---|---|---|
| 歩数 | Steps | 歩 | **合計** | `歩数` |
| 距離 | Walking + Running Distance | km | **合計** | `距離` |
| アクティブエネルギー | Active Calories | kcal | **合計** | `アクティブ` |
| 安静時消費エネルギー | Resting Calories | kcal | **合計** | `安静時` |
| 上った階数 | Flights Climbed | 階 | **合計** | `階数` |
| 体重 | Weight | kg | 最新 ※ | `体重` |
| 体脂肪率 | Body Fat Percentage | % | 最新 ※ | `体脂肪` |
| BMI | Body Mass Index | 件 | 最新 ※ | `BMI` |
| 除脂肪体重 | Lean Body Mass | kg | 最新 ※ | `除脂肪` |
| 身長 | Height | cm | 最新 ※ | `身長` |
| 心拍数 | Heart Rate | 拍/分 | 最新 ※ | `心拍` |
| 歩幅 | Step Length | cm | 平均 | `歩幅` |

※「最新」の項目は「統計を計算」を使わず、①で **並び順=開始日・最新から / 制限オン・取得1項目** にします。

> **メモ**: 体重は「今日」だと、その日に体組成計に乗っていない場合に空になります。
> 毎日必ず値を入れたい場合は、開始日の条件を「**過去7日間**」にして最新1件を取ってください。

### 2-2. 送信する

「**URLの内容を取得**」アクションを追加し、次のように設定します。

- URL: `https://<デプロイURL>/api/health/sync`
- 方法: `POST`
- ヘッダー: `x-widget-token` に `WIDGET_TOKEN` の値
- 本文を要求: `JSON`

**「本文を要求」を JSON にすると、キー・型・値を1行ずつ登録する欄が出ます。**
ここに JSON の文章をそのまま貼り付けてはいけません（キー名が `{ "uid": ...` になってしまいます）。
**「新規フィールドを追加」で1行ずつ**登録します。入れ子は不要で、すべて同じ階層に並べて構いません。

| キー | 型 | 値 |
|---|---|---|
| `uid` | テキスト | FirebaseのユーザーID |
| `steps` | テキスト | 変数 `歩数` |
| `distanceKm` | テキスト | 変数 `距離` |
| `activeEnergy` | テキスト | 変数 `アクティブ` |
| `basalEnergy` | テキスト | 変数 `安静時` |
| `flightsClimbed` | テキスト | 変数 `階数` |
| `heartRate` | テキスト | 変数 `心拍` |
| `stepLength` | テキスト | 変数 `歩幅` |
| `weight` | テキスト | 変数 `体重` |
| `bodyFat` | テキスト | 変数 `体脂肪` |
| `bmi` | テキスト | 変数 `BMI` |
| `leanBodyMass` | テキスト | 変数 `除脂肪` |
| `height` | テキスト | 変数 `身長` |

型はすべて「テキスト」で構いません。サーバー側で数値に変換します。

**最初は `uid` と `steps` の2行だけ**にして、動作確認（2-3）まで通してから残りを足すのが確実です。

**空になる項目があっても構いません。** その項目だけ「未取得」として保存され、ほかは通常どおり記録されます。
アクティビティ系と体組成系は、どちらか片方だけでも送れます。

睡眠も同じように平らに書けます（詳しい取り方は §5）。

| キー | 型 | 値 |
|---|---|---|
| `sleepStart` | テキスト | 変数 `就寝` |
| `sleepEnd` | テキスト | 変数 `起床` |

`sleepEnd`（起床時刻）があれば睡眠の記録として保存されます。
ワークアウトのように配列を持つデータだけは、入れ子で書きます（型に「辞書」を選びます）。

平らな形と入れ子の形は混ぜて使えます。`activity` / `weight` / `sleep` を入れ子で書くこともできます
（両方書いた場合は入れ子のほうが優先されます）。

ワークアウトを送る場合はこの形です（ショートカットのバージョンによってはワークアウトを取り出せません）。

```json
  "workouts": [
    { "type": "running", "typeLabel": "ランニング",
      "start": "開始時刻", "end": "終了時刻",
      "activeEnergy": "消費カロリー", "distanceKm": "距離" }
  ]
```

### 2-3. 動作確認

ショートカットを手動で1回実行します。「URLの内容を取得」の結果に次のような JSON が返れば成功です。

```json
{ "success": true, "results": { "activity": { "ok": true, "date": "2026-07-31" }, "weight": { "ok": true } } }
```

- `404` / HTMLが返る … **エンドポイントがまだ本番にデプロイされていません**（URLの綴りも確認）
- `Unauthorized` … `x-widget-token` の値かヘッダー名が違います
- `Missing uid` … JSON の `uid` が空です
- `No data` … 送った項目が全部空、またはキー名が違います
- `Invalid JSON` … 本文の作り方が間違っています（キー欄に JSON 全文を貼っていませんか）
- `"ok": false` が一部だけ … その項目だけ失敗しています。ほかは保存されています

**値が 0 や空で送られてしまう場合**は、2-1 の①②を見直してください。
アクションが「フィルタを適用」になっている、または「統計を計算」を通していないのが原因です。

### `"steps": null` のように、送ったのに null になる場合

`8,421`（桁区切り）や `8,421 歩`（単位付き）といった表示用の文字列はサーバー側で数値に直すので、
それが原因になることはありません。null になるのは次のどれかです。

応答に `rejected` が付いていれば、**実際に届いた文字列がそこに出ます**。原因の特定に使ってください。

```json
{ "success": true, "results": { "activity": {
    "metrics": { "steps": null },
    "rejected": { "steps": "データなし" }     ← 届いた中身
} } }
```

| 状況 | 原因 | 対処 |
|---|---|---|
| `rejected` に文字列が出る | 数値として読めないものが届いている | その項目の①②を見直す |
| `rejected` が付かない（値が空だった） | 変数が空。検索が0件か、変数の設定漏れ | 検索アクションが「フィルタを適用」になっていないか確認 |
| 深夜に実行した | その時間帯はまだ「今日」のデータがほとんど無い | 日中に実行して確かめる |

**変数の中身を直接見る方法**: 「変数を設定」の直後に「**クイックルック**」アクションを置いて実行すると、
その時点の値が画面に表示されます。原因の切り分けにいちばん確実です。

Lifelog を開き直すと、ダッシュボードに「今日のからだ」カードが出ます。
**すぐ反映されない場合**、アプリは5分間データをキャッシュします。少し待つか、画面を下に引っ張って更新してください。

## 3. 毎日自動で実行する

1. 「ショートカット」アプリ →「オートメーション」
2. 「個人用オートメーション」を作成 →「時刻」
3. 実行時刻を **毎日12:00** に設定（前夜の睡眠が確定し、朝の体重測定も入っている時刻）
4. 作成したショートカットを選ぶ
5. 「**確認後に実行**」を**オフ**にする — 表示が「すぐに実行」になっていないと、通知を押すまで実行されません

歩数を当日中もっと正確にしたい場合は、同じオートメーションを **23:00** にもう1つ作ってください。
同じ日付のデータは上書き（マージ）されるので、何度実行しても重複しません。

## 4. うまくいかないときの切り分け

まず API が生きているか、直接叩いて確認します。

```bash
curl -i -X POST https://<デプロイURL>/api/health/sync \
  -H "x-widget-token: $WIDGET_TOKEN" \
  -H "content-type: application/json" \
  -d '{"uid":"<FirebaseのUID>","activity":{"steps":1234}}'
```

| 返ってきたもの | 原因 | 対処 |
|---|---|---|
| `401 Unauthorized` | `WIDGET_TOKEN` 不一致 | Vercel の環境変数と、ショートカットのヘッダーを見比べる |
| `400 Missing uid` | `uid` が空 | ショートカットの変数が正しく差し込まれているか確認 |
| `400 No activity metrics` | `activity` の中身が全部空 | ヘルスケア側にその日のデータがあるか確認 |
| `200` だが画面に出ない | アプリ側のキャッシュ（5分） | 少し待つ / 引っ張って更新 |
| 体重だけ出ない | その日に体組成計に乗っていない | 期間を「過去7日間」にして最新1件を取る |

## 5. 睡眠を追加する（Sleep Cycle などの睡眠アプリを使い始めたら）

睡眠アプリ（Sleep Cycle 等）で Apple ヘルスケア連携をオンにすると、
ヘルスケアの「睡眠」にデータが入るようになります。そこから2つの時刻を取って送ります。

### なぜ歩数と作り方が違うのか

歩数やカロリーは「数値のサンプル」なので「統計を計算 → 合計」で1日ぶんを出せます。
一方 **睡眠は数値ではなく「区間」のサンプル**（何時から何時まで眠っていたか）として保存されるため、
「統計を計算」が使えません。合計時間をショートカット側で出すことはできません。

そこで **就寝時刻と起床時刻だけを送り、臥床時間はサーバー側で計算します。**

### 5-1. 就寝時刻を取る

**① ヘルスケアサンプルを検索**

| 設定項目 | 値 |
|---|---|
| 種類 | 睡眠分析（Sleep Analysis） |
| 開始日 | が過去1日である |
| 並び順 | 開始日・**古い順** |
| 制限 | オン・取得1項目 |

**② ヘルスケアサンプルの詳細を取得** → 取得する項目: **開始日**

**③ 変数を設定** → 名前: `就寝`

### 5-2. 起床時刻を取る

**④ ヘルスケアサンプルを検索**

| 設定項目 | 値 |
|---|---|
| 種類 | 睡眠分析（Sleep Analysis） |
| 開始日 | が過去1日である |
| 並び順 | 終了日・**新しい順** |
| 制限 | オン・取得1項目 |

**⑤ ヘルスケアサンプルの詳細を取得** → 取得する項目: **終了日**

**⑥ 変数を設定** → 名前: `起床`

### 5-3. JSON に2行足す

| キー | 型 | 値 |
|---|---|---|
| `sleepStart` | テキスト | 変数 `就寝` |
| `sleepEnd` | テキスト | 変数 `起床` |

これで完了です。実行すると次のように返ります。

```json
"sleep": { "ok": true, "date": "2026-07-31",
           "sleep": { "inBedMinutes": 522, "asleepMinutes": null } }
```

- `inBedMinutes` … 就寝〜起床の時間。サーバーが計算します
- `asleepMinutes` … 実際に眠っていた時間。ショートカットからは取れないので `null` のままです
  （アプリは `asleepMinutes` が無ければ `inBedMinutes` を表示します）

### 5-4. 実行タイミングに注意

睡眠アプリがヘルスケアに書き込むのは**起床して計測を止めたあと**です。
オートメーションが 12:00 なら問題ありませんが、起床前に実行しても前夜のデータは入りません。

`sleep` の項目が `"ok": false` で `Missing or invalid sleepEnd` を返す場合は、
ヘルスケアの「睡眠」にまだデータが無いか、⑤で「終了日」以外を取っています。

### 睡眠だけ日付がずれて見えるとき

睡眠は「**その睡眠を引き起こした食事の日**」に紐づけて保存されます。

```
7/30 の朝に起床した睡眠 → 7/29 のデータとして保存
```

これは「7/29 の夕食 → その夜の睡眠」という因果を同じ日にそろえるための仕様です。
アプリ上では今日の画面に「昨夜の睡眠」として表示されるので、意識する必要はありません。
Firestore を直接見るときだけ、1日前を見てください。
