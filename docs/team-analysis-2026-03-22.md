## 1. elena-architect: エレナIP戦略レポート

### 現在のキャラクター性

#### 強み

- **感情の多面性**: 5つの感情モード (NORMAL/SCOLD/LOGIC/ENCOURAGE/CHEER) + スコア連動6段階表情
- **「アメとムチ」の設計**: カロリー超過→叱責、不足→食べるよう促す、余裕→明るく提案
- **「データ至上主義 x 感情」という独自軸**: 数字に基づいて本気で怒り、本気で喜ぶキャラクター
- **教育者としての側面**: Elena's Challengeでのクイズ出題

#### 弱み

- **バックストーリーが完全に不在**: 「何者なのか」の設定がない
- **キャラクター設定の不統一**: 6箇所のプロンプトで微妙に異なる肩書・口調指示
- **関係性の「成長」がない**: 毎回リセットされる。時間軸を持った関係性の深化がない
- **タイポ**: ElenaChallengeModal.jsに「Elenas's Point」

### ダイエットトレーナー → 習慣トレーナー 進化プラン

| Phase | 期間 | 内容 |
|:--|:--|:--|
| Phase 1 | 現在〜1ヶ月 | ダイエット領域の深化（プロンプト統一、記憶強化、関係性フェーズ導入） |
| Phase 2 | 1〜3ヶ月 | 習慣領域への拡張（睡眠・運動・水分トラッキング、クイズテーマ拡張） |
| Phase 3 | 3〜6ヶ月 | ライフコーチへの昇華（朝のルーティン、夜の振り返り、週次レポート） |

> 最重要原則: 食事という「毎日必ずやること」を起点に、他の習慣に接続する設計

### バックストーリー案

**エレナ・ヴァレンティーナ (Elena Valentina)**

- 年齢: 26歳 / 出身: イタリア・ナポリ
- 経歴: 栄養学を学び、自身もかつて過食とリバウンドに苦しんだ過去がある
- 信条: 「数字は嘘をつかない。でも、数字だけじゃ人は変われない。」
- 性格: 知的で論理的だが感情的になりやすい。ユーザーが頑張っている時は一緒に喜び、サボった時は本気で悲しむ

### ユーザーとの関係性 成長モデル

| フェーズ | 期間 | エレナの態度 | キーフレーズ |
|:--|:--|:--|:--|
| 出会い | 1-3日 | 礼儀正しい、教育的 | 「よろしくお願いします！一緒に頑張りましょう」 |
| 信頼構築 | 4-14日 | 率直さが増す、冗談も | 「もう遠慮しませんよ？」 |
| パートナー | 15-30日 | 対等、時に厳しく | 「あなたならできるって、知ってますから」 |
| 戦友 | 31日+ | 深い信頼、回想 | 「ここまで来たんですから、もう止まれませんよね」 |

## 2. ux-engineer: UI/UX分析レポート

### 良い点

- CSS変数によるデザインシステムの一貫性
- モバイルファーストのシングルカラム設計 + PullToRefresh
- 5タブ構成の食事記録（カメラ/検索/履歴/レシピ/手入力）
- 時刻ベースのデフォルト食事タイプ自動選択
- スコア連動のエレナ表情変化 + グラデーションヘッダー
- Optimistic UI（食事削除・タイプ変更を即時反映）

### 課題と改善提案

| 課題 | 改善案 |
|:--|:--|
| インラインスタイルの多用（1000行超/コンポーネント） | CSS Modules or tailwindcss への段階的移行 |
| alert() / confirm() の多用 | カスタムトースト/モーダルに統一 |
| 空状態の設計が弱い（「記録がありません」のみ） | エレナが登場して記録を促すEmptyStateコンポーネント |
| ヘッダーの情報密度が高い | ボトムナビゲーションバーに移行 |
| タップターゲットが小さい（削除ボタン等） | 最低44x44px確保（Apple HIG基準） |

### エレナの存在感を高めるUI改善案

1. **ダッシュボード常駐ウィジェット**: 上部にエレナアイコン+一言コメント（時刻・記録状況で動的変化）
2. **Empty Stateでの活用**: 記録なし状態でエレナが前面に登場し記録を促す
3. **スコアカウントアップアニメーション**: 数字がカウントアップ + 確定時に表情切替
4. **感情状態インジケーター**: ヘッダーにエレナアバターを常時表示（直近スコアで表情変化）
5. **記録完了時エレナコメント**: トーストで「○○kcal記録！目標まであと△△kcal」

### 習慣トラッカーUI設計案

- **習慣カード**: 各習慣の進捗バー + 連続日数（エレナ提案ラベル付き）
- **週次ヒートマップ**: 過去7日の達成状況をカレンダー風に表示
- **エレナ提案形式**: 「次のチャレンジはこれにしない？」→承認/却下
- **達成時演出**: エレナのリアクションアニメーション

## 3. backend-engineer: バックエンド分析レポート

### Firestore最適化

- `getQuizFromStock` / `getQuizStockCount` に limit がない → `limit(100)` 追加推奨
- `resetLeaderboard` にバッチ上限(500件)チェックがない
- `addSearchHistory` の重複チェックでクエリコスト蓄積

### Gemini API

| 問題 | 対策 |
|:--|:--|
| モデルフォールバック順序が関数ごとに異なる | 全関数で統一 |
| GoogleGenerativeAI を都度 new | モジュールレベルシングルトン化 |
| evaluateDailyLog が suggestNextMeal を内部呼出し (2重API) | プロンプト統合 or 分離 |
| プロンプトサイズが巨大 (2000トークン超) | 圧縮検討 |
| JSONパース `match(/\{[\s\S]*\}/)` が脆弱 | `responseMimeType: "application/json"` 活用 |

### セキュリティ

| 重要度 | 問題 | 対策 |
|:--|:--|:--|
| **高** | `NEXT_PUBLIC_GEMINI_API_KEY` フォールバック | 即削除。Server Actionsでは非公開キーのみ使用 |
| **中** | linkCodes に有効期限なし | createdAt から10分以内かチェック追加 |
| **中** | admin.js が NEXT_PUBLIC_ の projectId 使用 | 非公開変数で統一 |
| **低** | Cronジョブが開発環境で認証スキップ | 意図的だが要注意 |

### パフォーマンスボトルネック

| ボトルネック | 解決策 |
|:--|:--|
| evaluateDailyLog の Gemini 2重呼び出し | プロンプト統合 or 並列化 |
| LINE Webhook の `setTimeout(2000)` + AI呼び出し | 非同期処理への移行 |
| actions.js 1300行超の肥大化 | 6ファイルに機能別分割 |

### actions.js 推奨分割案

```
src/app/actions/
  image-analysis.js    # analyzeImageWithGemini
  food-search.js       # searchLocalFood, searchAiFood
  meal-advisor.js      # suggestNextMeal
  daily-evaluation.js  # evaluateDailyLog, evaluateSingleMeal
  recipe.js            # calculateRecipeHybrid
  gemini-client.js     # 共通: シングルトン, MODELS_TO_TRY, JSONパースヘルパー
```

## 4. critic: 批評・リスク分析レポート

### 非エンジニアの運用負荷

- actions.js の分割とプロンプト外部化は「すぐやるべき」
- **大規模アーキテクチャ変更（Redux等）は避けるべき** → Claude Codeで段階的リファクタリング可能な範囲に留める

### エレナIP一貫性の懸念

- エレナのキャラクター定義が **最低6つのプロンプト** に分散
- 各プロンプトで微妙に異なる性格描写 → **最優先で修正すべき**
- ELENA_PERSONA 定数として一箇所で管理するだけで大幅改善

### SNS展開のリスク

| リスク | 内容 |
|:--|:--|
| **高** | AIの叱責機能がボディシェイミングと受け取られる可能性。スクショが文脈なしで拡散されるリスク |
| **高** | 健康効果の直接的主張は景品表示法・薬機法リスク |
| **中** | AIキャラクターの発言には「AIによる参考情報です」の免責表示が必要 |
| **低** | 技術ストーリーの発信は安全で開発者コミュニティの注目も期待できる |

### 価値判断

**高い価値**: カメラ→AI分析→記録のコアフロー、エレナの日次評価、カロリー管理

**疑わしい価値**: DietShooter（コアバリューから外れる）、MealRanking（データ量不足）、Elena's Challenge（毎日使うかは疑問）

## 最終アクションプラン

### すぐやるべき（1-2週間）

1. **エレナのプロンプト定義を1箇所に集約** (ELENA_PERSONA定数)
2. **エレナのキャラクターシート作成** (バックストーリー、口調ルール、NGワード)
3. **actions.js の機能別ファイル分割** (6ファイルへ)
4. **NEXT_PUBLIC_GEMINI_API_KEY の削除** (セキュリティ)
5. **「Elenas's」タイポ修正**

### 後回し（1-3ヶ月）

1. エレナのダッシュボード常駐ウィジェット
2. alert/confirm をカスタムUI に置換
3. 習慣トラッカー機能の追加
4. LINE連携のリマインド強化
5. X公式アカウント開設・運用開始

### やらないほうがいい

1. Redux等の大規模状態管理導入 → Claude Codeでの保守困難
2. エレナの叱責トーン強化 → ボディシェイミングリスク
3. DietShooterの拡張 → コアバリューから外れる
4. 複数キャラクター追加 → エレナ単体のIP確立が先
5. 早期の課金機能 → 実証実験フェーズでは不要
